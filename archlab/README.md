# archlab：架构实验室

目标：在小规模上检验"比固定深度 Transformer 更好的架构"的想法。

## 当前实验：固定计算量 vs "想到状态收敛为止"

- **基线**：8 层标准 Transformer（约 40 万参数），计算量由层数固定。
- **循环模型**：同一个 block 反复执行（约 5.9 万参数），每步重新注入输入，内部状态收敛后自动停机。
- **任务**：前缀奇偶校验、二进制加法（测试集带有贯穿整个数的进位链）。训练长度 ≤ 20，测试长度 20 / 40 / 80 / 160。

```bash
python lab.py --task add --model baseline --seed 0
python lab.py --task add --model looped --window 2 --stab 1.0 --tag _local --seed 0
```

## 结果（整题全对的比例）

加法，3 个种子（`results2/`）：

| 模型 | n=20 | n=40 | n=80 | n=160 |
|---|---|---|---|---|
| 基线 Transformer | 1.00 / 1.00 / 1.00 | 0.82 / 0.85 / 0.88 | 0.54 / 0.57 / 0.64 | 0.11 / 0.13 / 0.23 |
| 循环 + 局部注意力 + 稳定性约束 | 1.00 / 1.00 / 1.00 | 0.97 / 1.00 / 0.99 | 0.99 / 0.60 / 1.00 | 0.77 / 0.48 / 0.98 |

奇偶校验，1 个种子（`results/`）：基线 0.28 / 0 / 0 / 0；循环 + 局部注意力 1.00 / 0.98 / 0.59 / 0.19。

## 过程中的发现

1. **只循环不够**：全局注意力的循环模型学到的是捷径，多给步数没有提升，长度泛化和基线一样差。
2. **局部注意力迫使模型学可重复的规则**：信息只能靠迭代传播，所需步数随题目长度增长。
3. **稳定性约束**（答案应是更新的不动点）让超出训练步数的迭代不再发散，也让"状态收敛即停机"可用。
4. **种子间方差大**：同一配置，有的种子在 8 倍长度上 98%，有的只有 48%。

## 局限

- 任务是玩具级的算法题，规模很小，结论不能外推到语言模型。
- 循环加局部更新的思路已有先例（Universal Transformer、Deep Thinking 网络、神经元胞自动机）。目前是复现并确认了这个现象，还没有新的贡献。
- 奇偶校验只跑了 1 个种子，且没有加稳定性约束。
